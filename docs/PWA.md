# Installable app and offline use

## What is built
- **Manifest** (`manifest.webmanifest`, generated by vite-plugin-pwa): name ShuvroMed, standalone, theme teal, starts at `/app`, three icons (192, 512, 512 maskable). Icon source: `public/icon.svg`, PNGs made by `scripts/make-icons.cjs` (our own design, not a scaffold logo).
- **Service worker** (`sw.js`, Workbox): saves the app shell (all JS, CSS, icons, the page itself, 806 KiB uncompressed) the first time the app opens. Any page address then opens offline.
- **Questions**: not part of the first download (a large bank would be a heavy first visit). Each subject file is saved the first time it is opened; **Settings → Use without internet → Save all questions** saves every subject at once. Question files are requested as `file.json?v=<contentVersion>`, so one saved URL is one fixed version: when content changes the version changes and the new file is fetched; the catalogue (`manifest.json`, `taxonomy.json`) is network-first with the saved copy as the offline fallback.
- **Saving all questions is all-or-nothing**: every file is checked with the same Zod schemas the app uses; if any is bad or cannot be fetched, nothing is saved and the message says so.
- **Updates**: `registerType: prompt`. A new version waits; a notice offers **Reload now** or **Later**. It looks for a new version about once an hour and on every visit. A tab that stays open for a very long time keeps the old version until the student taps Reload.
- **Offline status**: the header shows "Offline · answers are saved on this device" the moment the connection drops. Answers, bookmarks and notes were already local-first; they upload when the connection returns.
- Supabase requests are never cached by the worker (they go to another site), so sign-in and sync are always live.

## What does NOT work offline (by design)
- Signing in or up, password reset, sync, delete account, the admin page (all need Supabase). A student who is already signed in stays signed in while offline (the session is stored on the device) and can practise, review, and take mock exams.
- Subjects never opened and never saved are unavailable offline.

## Tested (real Chromium 360x740, `scripts/check-offline.cjs`, 24/24 at the site root AND at the `/shuvromed/` preview sub-path)
Manifest and icons valid; Chromium reports no installability errors; worker activates; "ready for offline" notice; Save-all saves 3 subjects; header turns Offline at once; cold reload of /app, /app/subjects, /app/settings, /app/analytics while offline; questions load, an answer is submitted and saved offline; back online works; update prompt appears, Later dismisses, Reload now installs; no CSP violations; no JavaScript errors. Unit tests: `src/test/pwa.test.tsx` (15).

## Not tested / limits
- Not run on a real phone; the real Android install prompt, home-screen icon cropping and airplane-mode behaviour are in the owner checks (docs/DEPLOY.md).
- iOS Safari (install via Share → Add to Home Screen; storage may be cleared after weeks without use) was not tested.
- Browser storage can be cleared by the browser under storage pressure. Backups (docs/BACKUP.md) remain the safety net.
- Chromium's offline emulation reports `navigator.onLine` wrongly on a freshly loaded offline page; the connection-drop path (the real event) is what is tested.
- Free Cloudflare Pages was not reachable from the build environment: caching headers were tested against an emulation, not against Cloudflare.
